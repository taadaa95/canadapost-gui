# Threat model

Last reviewed 2026-07-26. This model covers the desktop application, its local data, Node workers, embedded browser, backups, release artifacts, and update metadata.

| Threat | Assets and trust boundary | Attacker capability | Controls and verification | Residual risk |
|---|---|---|---|---|
| Local credential theft | OS user data, keyring, credential files | Read files or run code as the user | `safeStorage` preferred; owner-only paths; AES-GCM fallback key separated from ciphertext; credentials excluded from renderer, DB, backup and diagnostics; storage tests | Malware running as the user can observe use or steal the fallback key. |
| Malicious project/archive content | Source/release boundary | Insert secrets, runtime data, symlinks or unexpected files | Explicit release allowlist, prohibited names/segments, redacting secret scan, clean Git materialization, manifest/checksums, extract-and-rescan, CI and release-content tests | Novel secrets may evade pattern matching; reviewer must inspect the manifest. |
| Malicious backup | Backup/import boundary | Supply traversal, zip bomb, corrupted or forged content | Versioned scrypt/AES-256-GCM envelope, authenticated header, checksum, compressed/uncompressed/entry/ratio limits, safe paths, DB integrity check, rollback copy, security tests | A trusted but semantically harmful old database may still contain unwanted records. |
| Renderer compromise and IPC abuse | Main/renderer boundary | Run script in the renderer | CSP, context isolation, Node integration off, sandbox on, narrow preload methods, bounded IPC, path confinement, arbitrary window opens denied, tests | The preload surface remains substantial and should continue to be split with the main monolith. |
| Arbitrary navigation | Embedded web boundary | Redirect or open a tab to an attacker origin | Production HTTPS Canada Post allowlist; exact loopback origin only in test mode; navigation/new-window/download/permission blocking; mock redirect/origin tests | A compromised allowed Canada Post origin remains trusted for workflow rendering. |
| Browser-session theft | Persistent browser partition | Read cookies/profile on disk or through a compromised process | Per-user profile, loopback CDP, randomized port, target token, sandbox, clear-session/profile control and audit | Local malware with user privileges may steal the profile or attach during a run. |
| CDP attachment | Loopback debugging port | Local process connects to CDP | Random port, loopback address, target token and page verification; process lifetime bounded | Another process running as the user can scan local ports. |
| Dependency compromise | npm/build boundary | Publish a malicious dependency or build script | Locked dependencies, production audit, SBOM/licence inventory, clean CI, package-content scan; dev audit findings recorded | npm lifecycle scripts and transitive build dependencies remain a supply-chain risk. |
| Update compromise/downgrade | Update metadata and artifact boundary | Replace metadata/artifact or serve an old version | Ed25519 metadata verification, SHA-256 artifact verification, channel enforcement, HTTPS, downgrade block, fail closed without a trusted key | No production key or publishing service exists yet; updates remain disabled/manual. |
| Log/diagnostic leakage | App-to-support boundary | Cause sensitive values to enter errors or logs | Structured redaction, URL query removal, tracking masking, shareable package rescan, local-only crash report with review, tests | Free-form text may evade redaction; users must review before sharing. |
| Tracking/address exposure | Filesystem/UI/export boundary | Read exports, evidence or screen | Owner-only runtime paths, release exclusions, backups encrypted, crash/diagnostic redaction, explicit exports | Authorized desktop users can view business records; shoulder surfing is not prevented. |
| Duplicate or uncertain claim | Worker/account boundary | Crash or delay around final submit | Attempt persisted before action, final click never retried after uncertainty, terminal outcomes non-retryable, unknown outcomes reconciled, queue snapshot and immediate revalidation, fault points | Only a human account check can resolve some ambiguous outcomes. |
| Database corruption | SQLite/runtime boundary | Crash, disk fault or malicious edit | WAL/FULL sync, forward-only transactional migrations, integrity checks, encrypted backups, restore rollback, immutable evidence triggers | Hardware failure between filesystem operations may still require manual recovery. |
| Untrusted policy/localization data | Bundled configuration boundary | Modify rules or translations | Packaged source allowlist, schemas, deterministic hashes, locale-key parity, conservative manual-review fallback | Policy changes after publication require a new reviewed release. |

Security verification is performed by `npm test`, `npm run lint`, `npm run typecheck`, `npm run secret-scan`, `npm run release:audit`, package auditing, mock-portal tests, Electron sandbox E2E, and the manual release checklist.
