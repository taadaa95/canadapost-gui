# Canada Post Claim Runner 0.4.2

Version 0.4.2 is a product-facing workflow cleanup release:

- Settings now includes a seven-step **Guided Canada Post Setup** assistant matching the recorded Developer Portal flow: **Sign in**, **Verify your account**, **Choose your business**, **Create your Claim Runner app**, **Save API credentials**, **Enable Tracking API**, and **Finish**. It starts at the Developer Portal and adapts to optional MFA, session-limit, already-authenticated, multiple-business, and existing-Production-app states.
- The assistant recognizes the recorded accessible controls from User menu → Sign in through Production app creation and the **App credentials generated** screen. It guides manual Copy API Key/Copy API Secret entry before OK, then follows the actual dashboard order to **API products → Add API product → Tracking API**. No remote Password, Access code, API Key, or API Secret value is read, compared, logged, or stored.
- Customer-number discovery prioritizes explicit labels and authenticated Developer Portal **BUSINESS (NUMBER)** selector entries, followed by **Viewing page as** and recognized business summaries. It returns business name plus number for explicit confirmation, does not confuse an 8-digit Web Username with a customer number, and prompts before replacing a saved customer number.
- The closed authenticated current-business link receives the standard yellow action guidance and remains user-controlled. A bounded structural reader uses **View organization settings** to handle multiline **Viewing page as / BUSINESS / (NUMBER)** markup; explicit organization-settings and Create-new-app Customer number fields provide fallback verification and surface conflicts instead of silently replacing the draft.
- Verification distinguishes the method-selection radio page from actual access-code and Security question Answer challenges. Active structural overlays own every highlight even without `role="dialog"`, and the authoritative API-product sequence is **Add API product → accessible Get access to Tracking → exact link Add inside the Tracking confirmation overlay**. The exact Tracking access link is centered automatically without being clicked.
- Callout badges are collision-placed outside their targets and fall back to ring/glow only. The desktop guidance panel is wider, presents one action at a time, and reserves the full readiness checklist for Finish.
- Guided fields and the standard Settings form share one in-memory draft. Values mirror immediately but persist only through **Save & Finish** and the existing secure save path; closing without saving restores the prior Settings draft.
- Page highlighting remains progressive enhancement: one primary action receives the 4px pulsing outline and a collision-placed, non-intercepting callout. Finish uses an explicit local success surface, clears classifier-fallback copy and target-search controls, marks completed steps, and emphasizes **Save & Finish**.
- Approved same-tab Canada Post navigation and redirects now run untouched in Chromium instead of being canceled or replayed as hardcoded loads. The hostname policy applies only to user/top-level destinations, not scripts, styles, images, fonts, CAPTCHA, authentication resources, or subframes. Actual popup requests retain separate guarded handling and POST data; arbitrary third-party top-level destinations remain blocked.
- Every open destroys any prior Setup instance and creates a fresh `WebContentsView`/webContents generation in the persistent Canada Post partition. Generation-scoped listeners and asynchronous guards prevent old navigation, load, classifier, candidate, and highlight work from mutating a reopened session. Close never waits indefinitely for page JavaScript, removes listeners, detaches/destroys the view, clears temporary fields and controller promises, and releases the operation lease in `finally`.
- A bounded browser-start watchdog prevents permanent **Preparing** state. Failure displays **Canada Post browser could not start** with **Retry browser** and **Close Setup**; Retry destroys the failed generation and creates another one. Classifier misses remain guide-only and cannot change browser readiness or retain the operation lease after close.
- After verification or session handling, a bounded quiescence check lets Canada's transient authenticated shells and redirects settle before business-menu assistance begins. The account confirmation card is stacked and replaced by an explicit **Business confirmed** state; evidence values use no pulsing action overlay, and main-frame loading immediately removes stale callouts.
- Create-app guidance advances through Production selection, non-empty App name, then Create. Credential guidance advances through separate remote-copy and local-paste phases, never reads the clipboard, keeps the secret masked, and offers OK only after both draft values exist.
- Tracking 2.0 is identified as the required product. Confirmation overlays are parsed for safe product/version/plan metadata: supported Tracking guides the exact Add link, while any other product guides Back and cannot satisfy completion—even if the user adds that unrelated product anyway.
- A default-on **Guidance sounds** switch inside Guided Setup uses short generated ascending/descending tones plus equivalent visual status. The existing non-sensitive config stores the preference, and generation-scoped semantic event deduplication prevents repeated classifier/DOM refresh sounds.
- Business discovery is now explicitly user-driven: after settling, the unique dynamic current-business link receives the full action highlight and Claim Runner never opens it automatically. Local API Key and masked API Secret paste fields use matching pulse/glow/callout treatment after each remote Copy action.
- API-product confirmations are parsed only from the active topmost overlay. Product name, version, plan, overlay identity, and a new per-selection attempt ID form the classification identity; returning to the catalogue clears the payload before Rating, Returns, Shipping, Tracking, or another selection is evaluated from scratch.
- A persistent header provides safe browser-history **Back**, confirmation-protected **Start over**, accessible Guidance sounds On/Off switch, and Close. Stable unrelated approved Canada Post pages produce contextual off-flow guidance; Back never reconstructs a GET/POST, while Start over destroys the old generation/history but preserves the unsaved setup draft, one-time credentials, sound preference, and persistent authenticated partition.
- Generated tones use a roughly three-times-higher effective amplitude with a bounded master stage. Credential capture retains a single durable state message instead of displaying an identical transient duplicate.
- Step 1 has no date inputs. At the instant a normal run starts, the main process computes today plus the preceding 34 Toronto calendar dates (35 inclusive dates). The established maximum-30-day segmentation therefore processes a 35-day window as 30 days plus 5 days while preserving adaptive retry splitting.
- Step 2 builds an in-memory union of current Step 1 rows and schema-8 current promoted classifications that have no authoritative successful delivery and remain in an explicit active/nonterminal lifecycle. Current imports win mutable enrichment on duplicates, while the database preserves the original Delivery Standard. Timeouts, HTTP failures, parser failures, and incomplete runs promote no replacement state, so unresolved shipments remain eligible next time.
- An eventual successful delivery on or before the original standard becomes ON_TIME and retains the strict existing cache optimization. Delivery after the original standard becomes LATE_CANDIDATE for supervised Step 3. Missing original standards remain REVIEW_REQUIRED; explicit return-to-sender evidence is terminal, and ambiguous evidence is retained conservatively.
- Step 2 removes advanced diagnostic and incomplete-run recovery controls from the normal workflow. It remains an automatic fresh tracking run and no longer requires the normal-user diagnostic gate.
- Claim History removes **Mark submitted**, **Mark not submitted**, and **Approve retry** while preserving evidence, historical statuses, reconciliation records, and audit data.
- A successful settings save displays **Settings saved**. Credential encryption, OS-keyring detection, and AES-256-GCM fallback behavior are unchanged.
- The visible unsigned-development-build badge is removed without changing release signing or safety infrastructure.
- Results notification badges now hide completely at zero, increment for off-tab results, clear when Results opens, retain an accurate nonzero result count, and reset to a hidden zero state.
- The normal application now always uses the production Tracking API environment; the obsolete Settings selector is removed and legacy non-production labels cannot route a normal run away from production.
- Customer-facing Advanced Settings utilities, Import CSV, Data Folder, Logs, Reset UI, and the Step 3 browser-profile reset button are removed without changing Step 1 imports, logging, recovery internals, secure storage, or the persistent Canada Post browser partition.
- Step 1, Step 2, and Step 3 execution buttons share compact dimensions. Step 3 now includes a localized **Automated browser** notice telling users to leave the browser alone during normal submissions and explaining that Claim Runner pauses explicitly for login, verification, or CAPTCHA input.
- Database schema remains version 8.
